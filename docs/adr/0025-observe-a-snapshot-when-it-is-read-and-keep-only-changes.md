# Observe a snapshot when it is read, and keep only its changes

An Observed Snapshot has none of what ADR 0014 dates a Health Record by. Samsung Health returns an aggregate, a goal or the profile with no UID, no source and no modification time, so there is no stable source instant to put in `observedAt`, and a snapshot is identified instead by its kind and its Snapshot Window: one local hour for steps and activity totals, one local day for goals, none for the profile. The window's end was rejected as the observation time: today's total and a total the watch corrected days later would carry the same instant with different content, and nothing could say which of them is current.

`observedAt` is therefore the moment the application read the snapshot, and the rule that keeps an hourly import from storing a copy of every window it re-reads moves out of the timestamp and into the comparison. The content digest of a snapshot observation excludes `observedAt`, and the API stores an observation only when its digest differs from that of the observation immediately before it in observation time; otherwise it answers `already_present` and the earlier `observedAt` stands as the first moment that content was seen. A value that returns to one seen before (A, then B, then A) is stored again, because the comparison is with the predecessor and not with every observation ever held, so the uniqueness of identity and digest that Observed Record Versions rely on does not apply to snapshots. An observation that arrives late is compared with its predecessor in observation time, not with the last one to arrive, and the Current Observed Snapshot is the one with the largest `observedAt`, as ADR 0012 decides currency, so arriving late never makes an observation current.

This is what makes re-reading cheap enough to be the only recovery a snapshot has. There is no changes feed for aggregates, goals or the profile, so every run re-reads from the last closed window up to now, the daily overlap of ADR 0017 re-reads the last seven days, and the profile is read on every run; an empty window is sent as an empty observation, because only that lets a total deleted at the source stop being current. Without the comparison each of those reads would grow the history; with it, only a change does.

Snapshots travel in a batch of their own, introduced by Ingestion Contract Version 3, and are kept in their own immutable tables beside those of Health Records, so the two dating rules never share a constraint. This is hard to reverse: the window sizes fix every snapshot's identity, and the observations stored under this rule cannot be reinterpreted under another without a Full Purge.
