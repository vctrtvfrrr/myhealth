# Import associated data inside the record that carries it

Data that only exists attached to a Health Record — today the route of an exercise — is imported as part of that record and preserved inside its envelope. It is never read, mapped, identified or delivered on its own, because Samsung Health exposes no read for it: the route is a value inside the sessions of the exercise, and the Health Category it belongs to exists only so that its read permission can be asked for and its Permission State observed. A capability entry says so with the `ASSOCIATED` read operation, and the catalog holds no capability for the category itself.

The consequence is that the associated data is disclosed or not by a permission the parent record does not need. An exercise imports whether or not the location permission was granted, and what a denied permission produces is an exercise without a route, which is the same shape an indoor exercise produces. The two are not told apart, and nothing tries to: the source does not distinguish them either, and a mapper that guessed would be inventing the difference. What the Data Owner sees instead is the Permission State of the category, which the permissions screen already shows under the exercise.

The route reaches the read model through the normalized payload rather than by unnesting the source payload in SQL. The source payload is preserved under the names Samsung Health chose, and a view reading those names would couple a query to the SDK a future version could rename, with nothing to fail before a deploy. The normalized payload is this repository's own vocabulary, which is what every other view already reads, so the route is projected there and the view knows nothing about the SDK.

Inside the route, a point states its unit in the name of each key — `latitudeDegrees`, `altitudeMeters` — instead of carrying the `{value, unit}` shape the scalar quantities use. A route is thousands of points long and would otherwise repeat a unit as often as it repeats a coordinate. The cost is two shapes in one payload; the unit of a point is then asserted by the contract rather than validated per value, which is stronger for a key that cannot be wrong at runtime and weaker as a description a reader can inspect.

The relational projection is a view of its own, one row per location, ordered by the position the source reported. A track is queried and plotted per point, and the exercise itself has nothing to say per point. It derives from the same Current Health Record projection as the exercise, so a Source Removal takes the route out with the record it belonged to, without erasing either from the preserved Observed Record Versions.
