# Keep the device token in Room without its own encryption

The application keeps the Ingestion Device token in plain text in the same Room database as the outbox, instead of encrypting it with an Android Keystore key as the spec first said. The token sits next to outbox payloads that are themselves plain health data, so a Keystore key would protect the credential while leaving the more sensitive data beside it readable to anyone who can read the application sandbox. Encrypting the whole database was also weighed and rejected: it adds a native dependency and a migration of the existing database to a personal application whose only user is the Data Owner.

The accepted threat is anyone who reads the application sandbox — root access, forensic extraction of the phone, or a device-to-device transfer to another phone — obtaining a token that lets them deliver forged Health Records until the Data Owner runs `device revoke` or `device rotate`. The token grants no read access, because the ingestion API has no query endpoint, and the ingestion API keeps only its digest. `allowBackup="false"` keeps the database out of cloud backups, but a device-to-device transfer still copies it, token and outbox included; that copy is accepted, and the new phone keeps delivering as the same Ingestion Device.
