# Recover by re-reading rather than by trusting a cursor

A Sync Cursor is the only thing standing between the Personal Health History and a change nobody reported, and it is a position on a phone. Three mechanisms exist so that no divergence depends on it being right.

Once a day, before reading, a run pulls the cursor of an incremental category back over the seven days behind it. The window is walked again on its own, so a late change inside it reaches the Current Health Record even where the changes feed of ADR 0016 never reported it. It is daily rather than hourly because it re-delivers everything inside the window, and an hourly overlap would spend most of a run's Outbox on observations the API already holds. It never reaches behind the stretch the initial load fixed, since outside it there is nothing this cursor ever read. The instant of the last overlap is kept on the cursor and shown on the screen, so that "it is executed" is something the Data Owner can see rather than something the code claims.

The Data Owner can also ask for a full reconciliation, which restarts the walk of the whole accessible history of every granted category and trusts no cursor at all. It is the recovery for local state that was lost or is suspected wrong, and it is safe to ask for at any moment: a re-read renders identically and the ingestion answers `already_present` for every observation it already holds. A reinstallation is the same situation reached without asking — the device keeps nothing, the initial load starts from the history floor again, and the Personal Health History does not grow a second copy of itself. It is asked for under its own WorkManager unique name, because the ordinary manual request keeps whatever is already queued and a reconciliation the Data Owner pressed for has to happen.

What re-reading cannot do is recover a removal nobody observed. A removed record is absent from every time range read, so no amount of re-reading reports it, and a reconciliation restarts the changes read at the moment it is asked for rather than before the removal. A Health Record removed at the source while this application was not watching — between a reinstallation and the walk that follows it, before the update that first read the feed at all, or further back than the feed retains — therefore stays projected as present indefinitely. Nothing here narrows that window, and it is stated rather than implied: the mechanisms above bound divergence caused by a cursor, not divergence caused by not having been there. Closing it needs the application to tell the API which identities it did see, so that the API can conclude that a previously known identity now absent is removed. That is an inventory the ingestion contract does not carry, and adding it is a change to the contract and to the projection rather than another read on the device.

A stored cursor this build cannot interpret is answered the same way, and never with a default position. Defaulting forward would skip a stretch of history nothing would ever read again; defaulting back would claim a position that was never reached. Both are silent, which is the one thing a lost position must not be. The run that meets one writes a full re-read of that category, durably, and ends naming `CURSOR_UNRECOVERABLE` as how it went, so the next run performs the re-read whether or not anyone is watching. That check runs before the permission gate, because the condition is local and leaving it in place would let the ordinary write of how the run ended bury the unreadable row under a cursor that claims nothing was ever imported.

Only the position is treated this way. An outcome an older build recorded and this one does not know is dropped, because how a past run ended says nothing about where the import stands.

Both re-reads deliver observations the API already holds, so the count of imported records on the screen counts observations staged and not distinct Health Records. Making it distinct would mean the device keeping an index of everything it has ever sent, which is the second copy the Outbox exists not to be.
