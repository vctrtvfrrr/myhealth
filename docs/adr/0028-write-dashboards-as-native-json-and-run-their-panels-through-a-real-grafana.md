# Write dashboards as native JSON and run their panels through a real Grafana

The dashboards of the Personal Health History are written by hand as native Grafana JSON in `observability/dashboards/*.json`, and that file is the source: the classic dashboard model that the platform reconciler sends to `/api/dashboards/db`, never the v2 schema. A visual draft may start as a copy saved in a local Grafana, but it only counts once pasted into the file and cleaned of what the reconciler rejects, such as the built-in `-- Grafana --` annotation and `${DS_*}` placeholders. Generating the JSON from Kotlin with the Grafana Foundation SDK was rejected because the SDK is a public preview and the generated JSON would need either a commit kept in sync or a generation step before every deploy; Grafonnet was rejected because it brings a second language into the monorepo of ADR 0003; exporting from the UI as the source was rejected because every export carries noise the reconciler refuses or discards.

Panel queries use Grafana macros and template variables that only Grafana expands, so they are verified through a real Grafana rather than by restating the macros. An integration test of `:ingestion-api` fills the read model through the API, creates `myhealth_read` by executing `docs/sql/read-access.sql` as ADR 0013 already does, starts `grafana/grafana:13.1` with a `myhealth-read` datasource logged in as that account, and runs every panel of every dashboard through `/api/ds/query` for every value of "Agrupar por". Each panel must answer without error and with rows; exact values are asserted only where the panel's SQL carries a rule of its own, such as the local day or the goal in force. The image follows the platform's floating `13.1` tag, so a patch that breaks a panel fails here when it reaches the platform, and the tag moves when the platform changes minor version.

The rules of ADR-0008 of `codelab/infra` are restated in a unit test, because a generation the reconciler rejects blocks the deploy of the API: the local uid, its length and uniqueness, the allowed datasources, no datasource variables, no `${DS_*}`, and links only to dashboards of the same generation. Running the reconciler's own script was rejected because it would tie this CI to a private repository of the platform; the cost is following that ADR when it changes.

What the platform does to a dashboard before saving it, prefixing the uid as `myhealth--<uid>`, imposing the `App: myhealth` folder and forcing `editable: false`, is implemented once in Kotlin and used both by the test and by a Gradle task that writes the preview a local Grafana in `compose.dev.yml` provisions from files. A link between dashboards is therefore written as `/d/myhealth--<uid>` and resolves the same in the test, in the preview and on the platform. The Data Owner previews against production through an SSH tunnel as `myhealth_read`, whose password stays in a local variable outside Git, so a dashboard is judged on the real history with exactly the reach the platform has.

ADR 0005 and `observability/README.md` keep declaring the empty generation until the change that publishes the first dashboard, which amends ADR 0005 and rewrites the README to describe how a dashboard is written, tested and previewed.
